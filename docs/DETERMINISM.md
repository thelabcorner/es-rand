# ESRAND determinism contract

This document is normative for ESRAND 0.1.x.

The public package version and the deterministic sequence contract are related
but distinct. A refactor may change implementation structure, allocation
strategy, or performance without changing deterministic output. Any change that
alters seeded output, state interpretation, scalar mapping, byte order, or jump
semantics must be treated as a determinism-contract change.

The current frozen compatibility fingerprint is:

```text
79f898bd424a75f6d8d53310bf30c1ab4ad790f1cd9011a9c987aa968f2e5b3b
```

It is regenerated by `npm run determinism-fingerprint` over 512 seeded
cross-surface cases. Do not update that expected digest merely to make a test
pass.

## Contract identifiers

- generator ID: `xoshiro128**`
- generator algorithm version: `1`
- explicit seed-contract version: `1`
- state width: 128 bits
- forbidden state: `[0,0,0,0]`
- period: `2^128 - 1`
- cryptographic: **no**

Snapshots carry both the algorithm version and seed version.

## Generator transition: `xoshiro128**` 1.1

ESRAND v1 uses David Blackman and Sebastiano Vigna's `xoshiro128**` 1.1
transition/output function.

For state words `s0..s3`:

```text
result = rotl32((s1 * 5) mod 2^32, 7)
result = (result * 9) mod 2^32
t      = (s1 << 9) mod 2^32

s2 ^= s0
s3 ^= s1
s1 ^= s2
s0 ^= s3
s2 ^= t
s3 = rotl32(s3, 11)

return uint32(result)
```

The implementation stores hot state internally as signed int32 values because
ExtendScript bitwise operators already operate modulo `2^32`. Public outputs
and snapshots normalize to unsigned 32-bit words. That signed storage is an
implementation optimization, not a contract difference.

## Explicit seed contract v1

Supported explicit seeds are exactly:

1. finite JavaScript `number`
2. JavaScript `string`
3. `number[]` whose elements are all finite

The three domains use different 32-bit tags:

```text
number  "NUM1" = 0x4e554d31
string  "STR1" = 0x53545231
array   "ARR1" = 0x41525231
```

The canonical serialized byte stream is hashed with **MurmurHash3 x86_128**
using seed:

```text
"ESR1" = 0x45535231
```

All packed words and scalar fields are serialized little-endian.

### Number seeds

A finite numeric seed is coerced with `>>> 0`.

Canonical bytes:

```text
u32le(NUMBER_TAG)
u32le(uint32(seed))
```

Total length: 8 bytes.

Therefore numeric seeds are intentionally modulo-`2^32`: for example,
`1` and `4294967297` are the same numeric seed.

The implementation contains a specialized 8-byte Murmur path for this case.
That optimization is required to remain byte-for-byte equivalent to the
serialization above.

### String seeds

Strings are serialized as exact JavaScript UTF-16 code units.

Canonical bytes:

```text
u32le(STRING_TAG)
u32le(string.length)
for each UTF-16 code unit c:
    u16le(c)
```

Total length: `8 + 2 * string.length` bytes.

This is deliberately not UTF-8. Lone surrogates are deterministic code units
and are not rejected.

The implementation packs two UTF-16 code units into each aligned uint32 word
where possible; this is only a storage/performance optimization. Murmur sees
the same byte sequence.

### Array seeds

Each element must be finite and is uint32-coerced.

Canonical bytes:

```text
u32le(ARRAY_TAG)
u32le(array.length)
for each element x:
    u32le(uint32(x))
```

Total length: `8 + 4 * array.length` bytes.

### MurmurHash3 x86_128

The hash algorithm is the canonical x86_128 MurmurHash3 structure from Austin
Appleby's public-domain SMHasher reference, expressed with ES3-safe 32-bit
arithmetic.

ESRAND does not assume `Math.imul` exists. Exact low-32-bit multiplication is
implemented with 16-bit limbs. Optimized fixed-constant Murmur paths inline the
same arithmetic to reduce old-ExtendScript call overhead.

The Murmur implementation is differential-tested against the
`murmurhash3js` oracle on **2,372 vectors** in the current release gate.

### Forbidden all-zero state repair

The first 128-bit Murmur result is used directly as xoshiro state unless all
four words are zero.

If it is all zero, ESRAND hashes the exact same canonical byte stream again
with:

```text
0x45535231 XOR 0x9e3779b9 = 0xdb642b88
```

If that second result is also all zero, the deterministic final fallback is:

```text
[1,0,0,0]
```

This repair path exists solely because xoshiro's all-zero state is forbidden.

## Automatic seeding

Calling `create()` without an explicit seed is intentionally outside the
reproducible seed contract.

Current auto-seed material is a numeric array containing:

1. low 32 bits of `new Date().getTime()`
2. high 32 bits of that wall-clock value
3. one native-`Math.random()`-derived word
4. a second independent native-`Math.random()`-derived word
5. an engine-local monotonic counter

That array is then processed through the normal **array seed v1** contract.

Two native draws are kept separately because Illustrator 30.6.0 /
ExtendScript 4.5.6 was live-observed to expose a 1/32768 output grid from
`Math.random()`; ESRAND does not pretend one such draw carries 32 bits of
entropy.

Automatic seeding is non-cryptographic and is not reproducible. ESRAND never
uses `$.hiresTimer` for seeding.

## Scalar mappings and state consumption

### `uint32()`

Consumes one xoshiro step and returns an integer in `[0, 2^32-1]`.

### `int32()`

Consumes one step and returns the same 32-bit result interpreted as signed.

### `random32()`

Consumes one step:

```text
uint32() / 2^32
```

Result range: `[0,1)`.

This lane carries 32 generator bits and is the fast fraction primitive.

### `random()`

Consumes two steps and constructs a 53-bit binary64 fraction:

```text
hi = uint32() >>> 5   // 27 bits
lo = uint32() >>> 6   // 26 bits

(hi * 2^26 + lo) / 2^53
```

Result range: `[0,1)`.

### `float32(min,max)`

For unequal finite bounds with finite span:

```text
min + (max - min) * random32()
```

Consumes one step. Equal bounds return the sole result without consuming state.

### `float(min,max)`

For unequal finite bounds with finite span:

```text
min + (max - min) * random()
```

Consumes two steps. Equal bounds return the sole result without consuming
state.

### `bool()`

Consumes one step and tests the high bit of the output word.

### `chance(p)`

Validates `0 <= p <= 1`, generates the same 53-bit fraction as `random()`,
and returns whether it is less than `p`.

It therefore consumes two steps even for `p=0` and `p=1`.

## Inclusive integer mapping

`int(min,max)` requires safe-integer endpoints, inclusive.

Let:

```text
width = max - min + 1
```

Requirements:

- `width > 0`
- `width <= 2^32`

For width 1, return `min` without consuming state.

For width `2^32`, consume one complete uint32 and return `min + word`.

For every other width:

```text
limit = 2^32 - (2^32 mod width)

do:
    word = uint32()
while word >= limit

return min + (word mod width)
```

This rejection step removes modulo bias. The number of consumed words is
therefore data-dependent only when rejection occurs.

`fillInt()` uses the same mapping. Its power-of-two bulk lane replaces modulo
with a mask only where the two operations are mathematically identical and
the rejection interval is the entire uint32 domain.

## Collections

### `choice(values)`

Uses the same unbiased bounded-index mapping as `int()`.

- empty input throws
- length 1 consumes no state
- sparse array-like holes may produce `undefined`

### `sample(values,count)`

Semantics are exact partial Fisher-Yates sampling without replacement.

The current implementation uses a sparse logical-position remap instead of
copying the complete input. This reduces temporary work from `O(length)` to
`O(count)` while preserving the same selected indices and RNG draw sequence
as partial Fisher-Yates.

### `shuffle(values)`

In-place Fisher-Yates. Returns the original array reference.

### `shuffled(values)`

Copies by numeric index, then performs the same Fisher-Yates mapping. The input
is not mutated.

No collection operation uses randomized `Array.sort`.

## Bytes and hexadecimal

`bytes(n)` / `fillBytes(target,n)` consume one output word per four bytes
and emit each word in little-endian byte order:

```text
word & 255
(word >>> 8) & 255
(word >>> 16) & 255
(word >>> 24) & 255
```

`hex(n)` emits the same first `n` generated bytes as lowercase hexadecimal.
Its lookup-table implementation is only a formatting optimization.

## Bulk-fill equivalence

Bulk APIs write from index 0 of the supplied target and return that same target.

If `count` is omitted, the target's existing length is the requested count.
If `count` is supplied, it determines how many output entries are written.

The release contract is:

- `fillUint32` = repeated `uint32`
- `fillRandom32` = repeated `random32`
- `fillRandom` = repeated `random`
- `fillFloat32` = repeated `float32`
- `fillFloat` = repeated `float`
- `fillBool` = repeated `bool`
- `fillChance` = repeated `chance`
- `fillInt` = repeated `int`
- `fillBytes` = repeated canonical byte emission

Loop unrolling and cached state writes may differ internally; output and final
state must not.

## Snapshots

`getState()` returns:

```js
{
  algorithm: "xoshiro128**",
  algorithmVersion: 1,
  seedVersion: 1,
  state: [s0, s1, s2, s3]
}
```

`fromState()` / `setState()` reject:

- incompatible algorithm ID
- incompatible algorithm version
- incompatible seed version
- malformed state length
- the forbidden all-zero state

A raw four-word array is accepted as an expert escape hatch. Persist the full
versioned snapshot when long-term compatibility matters.

## Jump and stream splitting

The official `xoshiro128**` jump polynomial advances by `2^64` steps:

```text
0x8764000b
0xf542d2d3
0x6fa035c3
0x77f2db5b
```

From `[1,2,3,4]`, `jump()` lands at:

```text
[2843103750,2038079848,1533207345,44816753]
```

The official long-jump polynomial advances by `2^96` steps:

```text
0xb523952e
0x0b6f099f
0xccf5a0ef
0x1c580662
```

From `[1,2,3,4]`, `longJump()` lands at:

```text
[1611968294,2125834322,966769569,3193880526]
```

`split()` returns a clone at the caller's current state and then advances the
caller by one official `2^64` jump.

## Persistent vendor semantics

`vendor-esrand.js` and its minified release counterpart inspect
`$.global.ESRAND`.

When the existing facade has the same package version, algorithm ID, algorithm
version, and seed version, it is retained. Re-evaluating the same compatible
vendor bundle therefore does not silently replace/reset the existing default
stream.

The standalone `ESRAND.jsx` artifact creates a fresh facade.

## Breaking-change rule

The following require an intentional determinism/version decision:

- changing the xoshiro transition or output function
- changing canonical explicit-seed serialization
- changing Murmur variant/hash seed/all-zero repair
- changing `random32()` or `random()` bit mapping
- changing integer rejection/mapping semantics
- changing byte order
- changing jump constants
- changing snapshot interpretation
- changing any bulk method so it no longer matches its scalar contract
- accepting an old versioned snapshot but interpreting it differently

Performance refactors that preserve all pinned vectors and the frozen
fingerprint do not require a determinism-version change.
